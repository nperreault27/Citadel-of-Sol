# Game

A mobile top-down tile-map game. **Phaser 4** renders the world, **React 19** draws the
interface over it, **Capacitor 8** packages it as an Android app bundle for Google Play.
Fully offline — no server, no accounts.

```bash
npm install
npm run assets:placeholder   # generates the placeholder art + map (already committed)
npm run dev                  # http://localhost:5173
```

`npm run dev` binds to `0.0.0.0`, so the "Network" URL it prints opens directly on a
phone on the same Wi-Fi. That is the fastest way to check touch controls — the desktop
browser's device emulation does not reproduce real touch behaviour.

## The React ↔ Phaser boundary

React reconciles on state change; Phaser runs a 60fps loop. Wiring them naively — Phaser
writing into React state, or React props feeding Phaser — gives you remounted canvases,
dropped frames and state tearing. So there are exactly **three channels**, each with one
job, and none of them imports React or Phaser:

| Channel | File | Carries | Frequency |
| --- | --- | --- | --- |
| `EventBus` | `src/bridge/EventBus.ts` | Discrete events, both directions | A few per second |
| `gameStore` | `src/state/store.ts` | Durable game state | On discrete events |
| `inputState` | `src/bridge/inputState.ts` | Joystick axes | Every frame |

### Rules that keep it fast

1. **Phaser never writes to the store per frame.** Every store write re-renders subscribed
   React components. Store writes are for discrete events — health changed, item gained.
   Continuous values (player x/y, velocity, camera scroll) live in Phaser and are read off
   the sprite at save time. `toSaveData()` takes position as an argument for this reason.

2. **Per-frame input goes through `inputState`, not React state.** The joystick writes to a
   plain mutable object and moves its knob by writing a transform straight to the DOM. Both
   through `useState` would re-render on every `pointermove`.

3. **Always pass a selector to `useGameStore`.** `useGameStore((s) => s.health)`, never
   `useGameStore()` — the latter subscribes the component to every field.

4. **Game rules live in `src/game/systems/`, which never imports Phaser.** Scenes
   orchestrate; systems decide. That is what makes the logic testable without a WebGL
   context — Phaser will not initialise under jsdom.

### Layout

The canvas is a fixed full-screen layer at `z-index: 0`. The React overlay sits at
`z-index: 1` with `pointer-events: none`, and each interactive widget sets
`pointer-events: auto`. Taps land on the world everywhere except on actual buttons,
with no hand-managed hit regions.

## Assets

Assets live in `public/assets/` and are fetched by Phaser's loader at runtime — they are
deliberately **not** `import`ed, because Phaser's loader takes URLs and Vite would rewrite
imports to hashed filenames. Every URL goes through `assetUrl()` in `src/game/assets.ts`
so it respects Vite's `base`.

The committed art is placeholder, generated by `scripts/generate-placeholder-assets.mjs`
(no dependencies — PNGs are encoded by hand with `node:zlib`). `overworld.json` is genuine
Tiled JSON: open it in [Tiled](https://www.mapeditor.org/), edit, and export over the top.

### How the map layers work

- **`ground`** — everything visible, rendered as a **`TilemapGPULayer`** (the `true` in
  `map.createLayer('ground', tileset, 0, 0, true)`). Phaser 4 draws it as a single quad
  whose cost is fixed per screen pixel rather than per visible tile. This is the biggest
  rendering win available to a scrolling tile map on a mid-range phone.
- **`walls`** — an invisible plain `TilemapLayer` used only for collision. A GPU layer is
  one quad and cannot answer per-tile collision queries, so the concerns are split. It also
  lets the lake look like water while blocking like stone.
- **`objects`** — a Tiled object layer. `spawn` sets the start position; objects typed
  `interactable` become dialog triggers, with `speaker` and pipe-separated `text`
  properties.

Set `physics.arcade.debug = true` in `src/game/config.ts` to see collision bodies.

## Saves

Versioned, validated, and never trusted:

```
load → JSON.parse → migrateToCurrent() → zod safeParse → use, or start fresh
```

Anything unreadable, unmigratable or schema-invalid yields a new save and sets
`saveWasReset`, which the UI surfaces to the player. A corrupt save that boots into a new
game is a bad day; one that crashes on launch is an uninstall.

Storage is `@capacitor/preferences` on device and `localStorage` in the browser. The native
path matters: WebView storage is wiped by "Clear cache" in app settings, which users do
routinely without expecting to lose progress. SharedPreferences survives it.

**Changing the save shape:** bump `CURRENT_SAVE_VERSION` in `src/save/schema.ts` *and* add
the matching entry to `migrations.ts`, keyed by the version being migrated *from*. Never
edit a migration once a build carrying it has shipped — someone's save depends on it
behaving exactly as it did.

## Android / Google Play

### Before the first `cap add android`

Set **`appId`** in `capacitor.config.ts`. It is permanent once the first build reaches
Play — changing it later means a new listing and losing every install and review.

```bash
npx cap add android
npm run cap:sync
npm run cap:open
```

### Target SDK 37

Capacitor 8 defaults to compile/target **36**. This project targets **37** (Android 17,
released June 2026) so it does not need migrating again before API 37 becomes mandatory in
August 2027. In `android/variables.gradle`:

```gradle
minSdkVersion = 24
compileSdkVersion = 37
targetSdkVersion = 37
```

> **`android:appCategory="game"` is load-bearing, not decoration.** At `targetSdk 37`
> Android ignores `screenOrientation`, `resizeableActivity` and aspect-ratio locks on
> displays ≥ 600dp, with no manifest opt-out — *except for games*, identified by that
> attribute. Without it the portrait lock silently stops applying on tablets and unfolded
> foldables. Test on a large-screen emulator, not just a phone.

Also set in `AndroidManifest.xml`: portrait lock, and an `@capacitor/app` back-button
handler (already implemented in `src/ui/hooks/useAndroidLifecycle.ts` — dialog closes,
then pause, then exit). Play reviewers do check back behaviour.

### Signing

```bash
cd android && ./gradlew bundleRelease
```

Keystores are gitignored (`*.keystore`, `*.jks`, `keystore.properties`). **Back the upload
keystore up somewhere outside this repo.** Losing it means never updating the listing again.

Push an AAB to the internal testing track early — while the game is still a colored
rectangle on a tile map. Signing, package naming and the first review pass are fiddly and
unrelated to gameplay; discovering them at launch is how ship dates slip.

## Traps already handled

- **`base: './'` in `vite.config.ts`.** The WebView serves from a local origin, so Vite's
  default absolute `/assets/...` paths 404 silently on device while working perfectly in
  the browser. The classic "white screen on device" bug.
- **StrictMode double-mount.** React 19 runs effects mount → unmount → mount in dev.
  Without the guard in `PhaserGame.tsx` you get two canvases, two game loops, doubled input
  and half the framerate — and only in dev.
- **`pointercancel`.** Android steals pointers for the notification shade and back gesture.
  Handling only `pointerup` leaves the player walking into a wall forever.
- **WebView CSS resets** in `globals.css` — text selection, long-press callout, tap
  highlight, overscroll bounce, pinch zoom, and `position: fixed` on `body` so the URL bar
  showing/hiding does not resize the canvas mid-game. Each rule kills a specific bug.

## Toolchain note

TypeScript is pinned to **6.0.3**, not 7.x. `typescript-eslint` (8.70.0, the current
release) peer-requires `typescript <6.1.0`; TypeScript 7 is the Go native rewrite and
changed the compiler API that typescript-eslint builds on. `tsc` alone would work at 7, but
type-aware linting would not. Revisit once typescript-eslint ships TS 7 support — it is a
two-line bump.
